trim 和範圍檢查：寫成函式

  1. 使用者常不小心多打空白，先用 trim() 去掉前後空白。
  2. 轉成數字後，還要檢查合不合理：步數不能是負的，一天也不太可能超過 100000。
  3. 不合法就回傳 null，所以回傳型別是 int?。
void main() {
  ⟦print(parseSteps(' 6500 '));⟧
  ⟦print(parseSteps('-30'));⟧
  ⟦print(parseSteps('200000'));⟧
}

⟦int? parseSteps(String text) {⟧
⟦  final n = int.tryParse(text.trim());⟧
⟦  if (n == null || n < 0 || n > 100000) {⟧
⟦    return null;⟧
⟦  }⟧
⟦  return n;⟧
⟦}⟧

為什麼 n < 0 不會出錯？|| 是從左算到右，左邊 n == null 成立就不會再往右算。走到 n < 0 時，Dart 已經知道 n 不是 null 了。

完成：步數解析器

  1. 7 筆「使用者輸入」放在 List<String> 裡。
  2. 寫 String? errorOf(String text)：合法回傳 null，不合法回傳原因。
  3. 合法的加總，最後印出有效筆數和合計。
void main() {
  ⟦final inputs = ['8000', ' 6500 ', 'abc', '', '-30', '12.5', '200000'];⟧
  ⟦var total = 0;⟧
  ⟦var ok = 0;⟧
  ⟦print('===== 步數解析器 =====');⟧
  ⟦for (final text in inputs) {⟧
  ⟦  final err = errorOf(text);⟧
  ⟦  if (err == null) {⟧
  ⟦    final n = int.parse(text.trim());⟧
  ⟦    total += n;⟧
  ⟦    ok++;⟧
  ⟦    print('「$text」→ $n 步');⟧
  ⟦  } else {⟧
  ⟦    print('「$text」→ 錯誤：$err');⟧
  ⟦  }⟧
  ⟦}⟧
  ⟦print('有效 $ok 筆，合計 $total 步');⟧
}

⟦String? errorOf(String text) {⟧
⟦  final t = text.trim();⟧
⟦  if (t.isEmpty) {⟧
⟦    return '沒有輸入';⟧
⟦  }⟧
⟦  final n = int.tryParse(t);⟧
⟦  if (n == null) {⟧
⟦    return '不是整數';⟧
⟦  }⟧
⟦  if (n < 0) {⟧
⟦    return '不能是負數';⟧
⟦  }⟧
⟦  if (n > 100000) {⟧
⟦    return '數字太大';⟧
⟦  }⟧
⟦  return null;⟧
⟦}⟧

單元 9 完成！這裡用 int.parse 是安全的，因為 errorOf 已經確認過它轉得過去。之後在 App 的輸入框驗證（單元 22），就是用這一套想法。
